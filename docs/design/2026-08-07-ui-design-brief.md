## 0. Что за продукт (минимум, который нужен дизайнеру)

gitfs монтирует git-репозиторий как диск: в Проводнике появляется том `G:\`, в
котором **история проекта — это папки**. Ветки, теги, коммиты, даты — папки;
отдельный файл открывается как папка со всеми своими версиями
(`0001-a3f9c21.cs`, `0002-8b04e77.cs`, `latest.cs`).

Одна фраза продукта: **«Коммиты — папки. Файл — тоже папка, внутри все его
версии».**

Аудитория — разработчики. Платформы — Windows (основная), Linux, macOS
(experimental). Характер — инженерный инструмент: сдержанный, точный,
моноширинный; никакого неона и «крипто-эстетики».

Ключевая особенность, определяющая весь бриф: **у продукта почти нет
собственных экранов.** Главный UI — это Проводник Windows, то есть чужой
интерфейс. Мы проектируем: (1) идентичность, (2) точки касания внутри
Проводника, (3) вывод CLI, (4) трей-менеджер (v2), (5) промо-ассеты README.

Существующий визуальный язык (из HTML-референса, можно развивать, а не копировать):
охристо-янтарный акцент «манильской папки» (#8A5C00 на светлом / #E3B341 на
тёмном), нейтрали камень/чернила, моноширинный Cascadia Code как характерный
шрифт, малые радиусы (2–4 px), обязательные светлая и тёмная темы.

## 1. Идентичность

### 1.1 Знак / логотип
- Направления на выбор (нужен один основной + упрощённая версия):
  «папка, из которой растёт граф коммитов»; буква диска `G:\` как леттеринг;
  дерево каталогов, сворачивающееся в букву g.
- Обязательное требование: знак читается в **16×16 px** (фавикон, трей, иконка
  диска) и масштабируется до 256×256. Проверка на светлом и тёмном фоне.
- Без текста внутри знака; название «gitfs» — леттеринг отдельно, строчными,
  моноширинная основа допустима.

### 1.2 Палитра и типографика
- Развить палитру референса: 1 акцент, 4–6 нейтралей, семантические
  (ok / warning / error) — отдельно от акцента; всё — в двух темах.
- Типографика: моноширинная гарнитура для кода/меток/данных + гуманистический
  гротеск для текста. Указать конкретные начертания и вебфонт-замены.

### 1.3 Поставка идентичности
- Гайд на 1–2 страницы: знак, охранное поле, минимальные размеры, палитра
  токенами (light/dark), типографика, примеры «можно/нельзя».

## 2. Точки касания в Проводнике (Windows) — основная поверхность

Проводник не перерисовать; мы управляем только этими элементами:

### 2.1 Иконка тома
- `.ico` диска, отображается у `G:\` в «Этот компьютер». Мультиразмер:
  16/24/32/48/256. Должна отличимо читаться рядом со стандартными дисками.

### 2.2 Иконки корневых папок пяти вьюх
Виртуальная ФС может отдавать `desktop.ini`, значит у корневых папок могут быть
свои иконки. Нужен комплект из пяти узнаваемых, стилистически единых:
- `branches\` — ветвление;
- `tags\` — метка/ярлык;
- `commits\` — узел графа / hex;
- `dates\` — календарь;
- `history\` — часы/слои версий. Это фирменная фича — иконка самая проработанная.
Плюс шестая, служебная: `.gitfs\` — приглушённая, «системная».

### 2.3 Файлы-маркеры
- `.truncated` (список обрезан) и `.gitfs-submodule` (заглушка сабмодуля):
  нужны иконки состояния «это не обычный файл, а знак от gitfs».

### 2.4 Что зафиксировано и не обсуждается
- Схема имён версий `NNNN-<sha>.<ext>` и `latest.<ext>` — задана спекой.
- Метка тома: `gitfs: <имя репозитория>`.

## 3. CLI — да, это тоже дизайн

Четыре команды: `mount`, `unmount`, `list`, `doctor`. Нужен гайд по выводу:

- **Макет строк** `doctor`: чек-лист со статусами ok / warning / fail,
  моноширинная сетка, выравнивание, что выделяется цветом, что нет.
  Каждый fail — с одной строкой «что сделать» (и ссылкой).
- **`list`**: таблица монтирований (репозиторий → точка → вьюхи → аптайм).
- **`mount`**: краткий успех одной строкой + как выглядит прогресс/ошибка.
- **Палитра ANSI** (8/256 цветов), поведение при `NO_COLOR` и в пайпе.
- **Тон ошибок**: без восклицаний и вины, формат «что случилось → как починить»,
  3–4 эталонных примера текста.

Формат поставки: текстовые макеты (моноширинные мокапы) + правила, не картинки.

## 4. Трей-менеджер (v2) — единственное «настоящее» GUI

Avalonia, Windows/Linux/macOS, светлая+тёмная. Проектируем сейчас, чтобы
идентичность легла сразу.

### 4.1 Иконка в трее — состояния
1. нет монтирований (покой);
2. смонтировано N (активность, бейдж количества);
3. деградация (переоткрытие пакетов, осиротевший overlay) — warning;
4. ошибка драйвера — error.
Windows: светлый и тёмный таскбар. macOS: template-image (монохром).

### 4.2 Меню трея
- Список монтирований: имя репо, точка (`G:\`), индикатор состояния;
  по клику — открыть в Проводнике.
- Действия на монтировании: открыть, размонтировать, показать лог.
- «Смонтировать…», «Doctor», «Настройки», «Выход».

### 4.3 Диалог монтирования (главный экран)
- Выбор репозитория (путь + недавние), выбор точки (свободные буквы дисков
  выпадающим списком / папка на POSIX).
- Пять вьюх — чекбоксы с однострочными пояснениями.
- Свёрнутая секция «Дополнительно»: `--history-ref`, лимиты (200/500), кэш
  (256 МБ), name-policy, read-only, keep-overlay.
- Валидация: занятая буква, не-репозиторий, отсутствующий WinFsp → каждое
  состояние с текстом и действием.
- Успех: тост «Смонтировано → открыть G:\».

### 4.4 Окно менеджера (опционально, если останется бюджет)
- Таблица монтирований со статусами; панель деталей: счётчики кэша (из
  `status.txt`), просмотр `log.txt`, кнопка doctor.

### 4.5 Первый запуск
- Онбординг из одного экрана: проверка WinFsp → если нет, объяснение и кнопка
  установки; затем «смонтируйте первый репозиторий».
- Пустые состояния всех списков.

## 5. Промо-ассеты README / GitHub

### 5.1 Hero-GIF — главный ассет проекта
Сториборд (снимаем реальный экран, дизайн задаёт композицию, темп, подписи):
1. терминал: `gitfs mount C:\repo G:` → одна строка успеха;
2. Проводник: открывается `G:\`, видны пять папок;
3. заход в `commits\a3f9c21\` — обычные файлы проекта;
4. заход в `history\src\Program.cs\` — **кульминация: файл стал папкой**;
5. открытие `0002-8b04e77.cs` в Блокноте;
6. финальный кадр-плашка: логотип + «Коммиты — папки».
Требования: ≤ 30 с, читаемо в превью GitHub (ширина ~800 px), подписи-плашки
в фирменном стиле, тёмная тема ОС.

### 5.2 Остальное
- Social preview GitHub 1280×640: знак + фраза + фрагмент дерева.
- Шапка README (светлая/тёмная через `picture`).
- Стиль для 2–3 схем README (согласовать с диаграммами HTML-референса).
- Бейджи: набор и порядок (CI, релиз, платформы, лицензия).

## 7. Ограничения и критерии приёмки

- Всё — в светлой и тёмной темах; иконки читаются в 16 px без деталей-мусора.
- Иконки Windows следуют пластике Windows 11; трей macOS — монохромный template.
- Семантические цвета не совпадают с акцентом.
- Никакого текста в иконках; никаких эмодзи как ассетов.
- Тон — инженерный инструмент, а не финтех-лендинг.
- Приёмка: знак в 16 px опознаётся среди стандартных иконок дисков; GIF понятен
  без звука и без чтения README; диалог монтирования проходит без подсказок
  человеком, который видит продукт впервые.

## 8. Что НЕ проектируем

- Сам Проводник/Finder и их поведение.
- Схему имён файлов и структуру дерева — зафиксированы техспекой.
- Синтаксис CLI-команд (только представление вывода).
- Лендинг и сайт — вне объёма v1 (кандидат на потом).
